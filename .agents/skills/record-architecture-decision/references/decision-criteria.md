# ADR decision criteria

Use an ADR when the choice changes one or more of:

- component ownership or dependency direction;
- public API, schema, data model, or temporal semantics;
- persistence, messaging, deployment, or recovery model;
- security, privacy, compliance, or secret boundary;
- agent autonomy, tool authority, evaluation, or human approval;
- a major dependency with material lock-in or operating cost;
- a settled project constraint that future work must not casually revisit.

Use an Issue or handoff update for scheduling, ordinary implementation detail, transient status, or reversible local refactoring.
