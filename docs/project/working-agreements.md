# Working agreements

## Public project policy

- Inspect existing artifacts and live state before asking factual questions or making changes.
- Preserve unrelated work and keep one write-capable owner per worktree.
- Prefer the smallest vertical slice with executable acceptance evidence.
- Keep GitHub Issues as canonical work objects and Projects as operational views.
- Record material architecture decisions in ADRs.
- Separate verified facts, reported claims, and inference.
- Run the same authoritative check locally and in CI; never satisfy an unresolved check with a successful no-op.
- Keep harness and product versions independent and record product release impact before independent approval.
- Never treat conversation history as durable project state.

## Preference scopes

- Commit rules that every contributor and agent must follow here or in `AGENTS.md`.
- Record machine-readable project choices in `harness/project.yaml`.
- Keep personal defaults in `.harness/preferences.local.json` unless deliberately promoted.
- Keep employer, customer, or confidential constraints in an approved private system, not a public template.

## Changes

Changes to these agreements require a reviewed repository change. A Learn phase may propose an update but cannot apply policy silently.
